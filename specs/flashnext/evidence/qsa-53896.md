## Headline

**Neither reference bug is present in PR #53896's QSA implementation.** Selected-token sparsity
is realized as a *gather* over only the top-k KV entries inside a bespoke Triton split-K GQA
kernel whose main loop is bounded by `TOPK`, never by `kv_length`; and the indexer top-k is a
GPU op (`torch.ops._C.cooperative_topk` / `persistent_topk` on CUDA,
`ops.top_k_per_row_decode` on ROCm) over a batched `[rows, columns]` logits tensor, with no
Python loop over `(batch_idx, query_idx)` and no host synchronization anywhere in the path.
This is not a literal port of the HF reference; it is a from-scratch paged/varlen rewrite.

The QSA code is **byte-identical** between the two checkouts. `diff -rq` over
`vllm/models/qwen4_exp/` reports differences only in `amd/model.py`, `amd/mtp.py`,
`amd/ple_layer.py`, `nvidia/model.py`, `nvidia/mtp.py`, `nvidia/ple_layer.py`, plus
`Only in …pr54129/vllm/models/qwen4_exp/nvidia: ple_mmap.py` **[M]**. Every `qsa*.py`,
`indexer_qsa.py`, and `common/qsa_cache.py` file is unchanged. **#54129 carries no newer QSA
code.**

## 1. BUG A — dense-behind-a-mask: **NOT PRESENT** (both prefill and decode)

### The attention call chain

`Qwen4ExpQSAAttention.forward` → custom op → `_run_qsa` → `impl.forward_qsa` →
`qsa_sparse_paged_attention`. There is **one** path; the inherited `FlashAttentionImpl.forward`
is never reached.

- `vllm/models/qwen4_exp/nvidia/qsa.py:396-428` — `forward()` computes q/k/v then dispatches to
  `torch.ops.vllm.qwen4_exp_qsa_with_output` (or the eager twin at :420). **[S]**
- `vllm/models/qwen4_exp/nvidia/qsa.py:436-458` — the custom op resolves the layer and calls
  `layer._run_qsa(...)`. **[S]**
- `vllm/models/qwen4_exp/nvidia/qsa.py:367-394` — `_run_qsa` runs the indexer, writes KV, then
  `impl.forward_qsa(..., token_to_req=side_metadata.token_to_req)`. **[S]**
- `vllm/models/qwen4_exp/nvidia/qsa.py:154-164` — `forward_qsa` imports and calls
  `qsa_sparse_paged_attention(query, key_cache, value_cache, logical_indices, block_table,
  token_to_req, output)`. `logical_indices = topk_buffer[:num_tokens]` (`:146`). **[S]**
- `vllm/models/qwen4_exp/nvidia/qsa.py:90-92` — `Qwen4ExpQSAFlashAttentionBackend.is_sparse()`
  returns `True`. **[S]**

### The kernel gathers; it does not mask

`_qsa_sparse_paged_gqa_splitk_kernel` — `vllm/models/qwen4_exp/nvidia/ops/qsa.py:193-358` **[S]**:

- `:256` `for tile in range(split_tile_start, split_tile_end)` where the tile bounds derive from
  `NUM_TILES` (`:254-255`), and `NUM_TILES = triton.cdiv(logical_indices.shape[1], block_n)`
  (`:875`). The loop trip count is **O(topk)**, independent of `kv_length`.
- `:258-262` loads `logical_token` from `indices_ptr` — i.e. the *selected* token id per column.
- `:264-281` translates that token id to `(logical_page, page_offset)` and resolves the physical
  page through `block_table`.
- `:282-299` loads **only those** K and V rows from the paged cache.
- `:300-315` does the flash-style online-softmax accumulation over exactly those gathered rows.
- `:303` `scores = tl.where(valid[None, :], scores, -1.0e20)` — the `-1e20` is applied only to
  *padding slots inside the top-k list* (`logical_token < 0`, out-of-range page), not to the
  unselected part of the KV. There is no full-`kv_length` score matrix anywhere in the file.

`qsa_sparse_paged_attention` — `:812-952` — passes `TOPK=logical_indices.shape[1]` (`:922`) as a
`tl.constexpr`. `logical_indices` has width `output_width = token_topk + compress_ratio - 1`
(`nvidia/indexer_qsa.py:170-172`). For the config-validated budget, that is a few thousand
columns regardless of a 256K context.

### Prefill vs decode

**There is no prefill/decode branch in the QSA attention path.** `grep -n "prefill\|decode"`
over `nvidia/qsa.py`, `nvidia/ops/qsa.py`, `nvidia/indexer_qsa.py` returns only: a docstring
(`qsa.py:62`), two context-parallelism rejections (`qsa.py:111`, `:196-197`), a causality check
(`qsa.py:203`), and one *tuning* comment (`ops/qsa.py:863`) **[M]**. The only prefill/decode
sensitivity is the split-K/tile heuristic at `ops/qsa.py:864-873`, selected from
`base_programs = q.shape[0] * k_cache.shape[2]` (`:859`) — same kernel, different `BLOCK_N` /
`num_splits`. Prefill runs the *same* gather kernel with one independent selection per token
(rows = `num_actual_tokens`), which is the correct per-query semantics, not a dense fallback.

There is also no short-context dense fallback: when fewer than `block_topk` blocks are visible,
the surplus columns are simply `-1` and are masked out inside the gather loop — asserted by
`tests/models/qwen4_exp/test_qsa_reference.py:840-862` (`test_qsa_selection_handles_no_complete_compressed_blocks`,
`assert torch.all(selected[0, 2:] == -1)`). **[S]**

**Caveat worth recording:** sparsity here is *compute-only*. The main KV cache is a full BF16
`FullAttentionSpec` (`nvidia/qsa.py:331-339`), so KV memory still scales with context; only the
attention FLOPs and the K/V traffic scale with `topk`.

## 2. BUG B — CPU/Python-loop top-k: **NOT PRESENT**

### Where top-k runs

`qsa_select_paged_tokens` — `vllm/models/qwen4_exp/nvidia/ops/qsa.py:743-809` **[S]**:

1. `:778-786` `qsa_mqa_paged(...)` → Triton kernel `_qsa_mqa_paged_kernel` (`:18-118`) writes a
   batched `[rows, columns]` fp32 `logits` tensor (`:636`) plus a per-row `visible_blocks`
   count (`:637`, stored at `:68-69`).
2. `:788-799` selects and calls the top-k **device op**:
   ```
   topk_op = (torch.ops._C.cooperative_topk if use_cooperative_topk
              else torch.ops._C.persistent_topk)
   topk_op(logits, visible_blocks, blocks, topk_workspace, block_topk, columns)
   ```
   `use_cooperative_topk` requires `blocks.shape[0] <= 32`, `logits.stride(0) % 4 == 0`,
   `has_device_capability(90)`, and not `is_device_capability_family(120)` (`:788-793`).
3. `:800-808` `expand_qsa_block_indices_cuda(...)` → Triton kernel `_expand_qsa_indices_kernel`
   (`:121-189`) expands each selected *block* to `compress_ratio` token ids and appends the
   causal tail — also on GPU.

On ROCm the third branch is used: `amd/ops/qsa.py:774-808` adds
`current_platform.is_cuda()` to the cooperative predicate and falls through to
`ops.top_k_per_row_decode(logits, 1, visible_blocks, blocks, blocks.shape[0],
logits.stride(0), logits.stride(1), block_topk)` — a pre-existing vLLM custom op
(`vllm/_custom_ops.py:3104-3123`, wrapping `torch.ops._C.top_k_per_row_decode`). **[S]**

### Is there *any* Python loop?

Yes, exactly one, and it is a **workspace-chunking loop over row batches, not a per-(batch,query)
loop**: `ops/qsa.py:775` `for row_start in range(0, rows, rows_per_chunk)` with
`rows_per_chunk = max(1, _LOGITS_WORKSPACE_BYTES // max(columns * 4, 1))` (`:767`) and
`_LOGITS_WORKSPACE_BYTES = 128 * 1024 * 1024` (`:14`). Each iteration processes up to
`rows_per_chunk` query rows in a single batched kernel + single batched top-k. **[S]**

`grep -n "^\s*for \|\.item()\|\.cpu()\|\.tolist()"` over `nvidia/ops/qsa.py`,
`nvidia/indexer_qsa.py`, `nvidia/qsa.py`, `amd/ops/qsa.py` returns **8 hits total, all of them
either `tl.range`/`tl.static_range` inside `@triton.jit` bodies or the chunking loop above; zero
`.item()`, zero `.cpu()`, zero `.tolist()`** **[M]**:

```
amd/ops/qsa.py:91   for head in tl.static_range(0, NUM_HEADS)       # triton
amd/ops/qsa.py:251  for tile in range(split_tile_start, ...)        # triton
amd/ops/qsa.py:508  for group_offset in tl.range(0, COMPRESS_RATIO) # triton
amd/ops/qsa.py:761  for row_start in range(0, rows, rows_per_chunk) # host chunking
nvidia/ops/qsa.py:87   for tile in tl.range(tile_start, tile_end, num_stages=STAGES)
nvidia/ops/qsa.py:256  for tile in range(split_tile_start, split_tile_end)
nvidia/ops/qsa.py:513  for group_offset in tl.range(0, COMPRESS_RATIO)
nvidia/ops/qsa.py:775  for row_start in range(0, rows, rows_per_chunk)
```

The docstring at `:754` is explicit: *"Score, select, and expand QSA indices without host
synchronization."* **[S]**

### How many times per step?

**Once per QSA (full-attention) layer per forward pass** — `_run_qsa` calls
`self.indexer(...)` unconditionally (`nvidia/qsa.py:367`), and `QSAIndexer.forward` ends in one
`qsa_select_paged_tokens` call (`nvidia/indexer_qsa.py:343-353`). Inside that call the top-k op
fires `ceil(rows / rows_per_chunk)` times **[M, arithmetic from `:767` and `:775`]**:

- decode, batch ≤ a few hundred: `rows` is small ⇒ **1** top-k launch per QSA layer per step.
- prefill: e.g. `columns = 65536` compressed blocks ⇒ `rows_per_chunk = 128MiB / 256KiB = 512`
  ⇒ an 8192-token prefill chunk ⇒ 16 launches per QSA layer.

The exact number of QSA layers is **UNDETERMINED** — it is `layer_types == "full_attention"`
from the checkpoint's `config.json`, which is not in the local model dir (see Artifacts).

The MTP/speculative path skips re-selection entirely on steps ≥ 1: `self.skip_topk`
(`nvidia/indexer_qsa.py:132`, honored at `:337-340`), toggled by
`nvidia/mtp.py:254-258 set_skip_topk` from `vllm/v1/spec_decode/llm_base_proposer.py:583-584,
611-612` and `vllm/v1/worker/gpu/spec_decode/mtp/speculator.py:41,54,58`. **[S]**

### Would these catch bug A or bug B?

**Bug A — partially, and only by construction.** The oracle at `:202-229` is itself a gather, so
a dense-behind-a-mask kernel that produced *numerically correct* output would still pass. What
the suite actually pins is the *interface*: `logical_indices` is the sole KV selector, and the
kernel is called with it. The structural guarantee that this is genuinely sparse comes from the
kernel source (§1), not from these tests.

**Bug B — no. Explicitly no.** A CPU-loop top-k that returned the same indices would pass every
assertion in the suite. Correctness tests are blind to performance defects. The one test that
comes close is the ROCm dispatch test (`test_qsa_amd.py:135-208`), which pins *which op* is
called — a genuine structural guard, but only on the ROCm branch, and only that
`top_k_per_row_decode` is invoked with the right arguments; there is no assertion anywhere that
`torch.topk` / a Python loop is *not* used on the CUDA branch. **There is no benchmark, no
kernel-launch-count assertion, and no `.item()`/host-sync guard in the suite.** **[M]**

### The PR's scoring graph, end to end

`nvidia/indexer_qsa.py:230-353` **[S]**:

1. `index_qk_proj(hidden)` → split into `index_n_heads * index_head_dim` (Q) and
   `index_kv_heads * index_head_dim` (K) (`:230-237`).
2. **Q**: `gemma_rmsnorm(q, q_layernorm.weight, eps)` (`:277-281`) → `apply_qsa_rope(rotary_emb,
   positions, q)` (`:282`). `apply_qsa_rope` (`:31-63`) reuses the *main attention's* rope cache
   and MRoPE composition, applying rotation only to `[..., :rotary_dim]` and concatenating the
   untouched tail (`:58-63`).
3. **K**: raw (un-normed, un-roped) K is cached; `qsa_compress_groups_with_ratio` mean-pools
   `compress_ratio` consecutive raw keys (`:294-305`; kernel `ops/qsa.py:442-588`, the mean at
   `:539-545` `accumulator / COMPRESS_RATIO`), then `gemma_rmsnorm` (`:306-310`), then
   `apply_qsa_rope` at **the first position of the group** (`first_positions`, `:311-319`).
4. **Score**: `_qsa_mqa_paged_kernel` `ops/qsa.py:111-113` —
   `scores = tl.dot(keys, query); scores = max(scores, 0.0); score = sum(scores, axis=1) /
   score_divisor` with `score_divisor = sqrt(head_dim)` (`:628`). That is per-head dot → **ReLU**
   → sum over heads → `/sqrt(d)`.
5. Top-k over *blocks*, then expand to tokens + causal tail (§2).

The fused NVIDIA kernel `qsa_pre_indexer` (`nvidia/ops/qsa_pre_indexer.py:403-424`, docstring
*"Normalize Q, compress K, then update the circular raw state"*) is asserted equivalent to this
unfused path by `test_qsa_pre_indexer.py:293-295`, including bitwise raw-K equality. **[S]**
