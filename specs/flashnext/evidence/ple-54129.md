## 2. TP semantics of the mmap path

### Vocab-parallel path: a per-lookup all-reduce
`vllm/model_executor/layers/vocab_parallel_embedding.py:490-518` [S]:
```python
def forward(self, input_):
    if self.tp_size > 1:
        masked_input, input_mask = get_masked_input_and_mask(...)   # :493-500
    ...
    output_parallel = self.quant_method.embedding(self, masked_input.long())   # :504
    if self.tp_size > 1:
        if output_parallel.dtype in (torch.float8_e4m3fn, torch.float8_e5m2):
            comm_output = output_parallel.view(torch.int8)                     # :512
            comm_output.masked_fill_(input_mask.unsqueeze(-1), 0)              # :513
            output = tensor_model_parallel_all_reduce(comm_output)             # :514
            return output.view(output_parallel.dtype)
        output_parallel.masked_fill_(input_mask.unsqueeze(-1), 0)              # :516
        return tensor_model_parallel_all_reduce(output_parallel)               # :517
    return output_parallel
```
The FP8-as-int8-SUM fast path (`:507-515`) is **introduced by this PR family** — see `pr54129.diff` hunk at `pr54129.diff:8770-8783`. [S] Rows are sharded across ranks (`num_embeddings_per_partition = divide(num_embeddings_padded, tp_size)`, `:313-314`), each vocab row has exactly one owner, so SUM reconstructs it.

So: **yes, one `tensor_model_parallel_all_reduce` per PLE lookup, per PLE layer, per forward** whenever `tp_size > 1`.

### Mmap path: plain `nn.Module`, whole table per rank, no collective
`MmapNgramEmbedding` is declared `class MmapNgramEmbedding(nn.Module)` at `nvidia/ple_mmap.py:506` [S] and constructed with the **full padded vocab**: `ple_mmap.MmapNgramEmbedding(padded_vocab_size, self.head_dim)` at `nvidia/ple_layer.py:288-290` [S] — the identical `padded_vocab_size` handed to the vocab-parallel constructor in the `else:` branch at `:292-293`.

Its `forward` (`ple_mmap.py:545-573`) contains **no collective, no mask, no rank arithmetic**:
```
$ grep -n 'rank\|tp_\|world_size\|parallel\|all_reduce\|distributed' vllm/models/qwen4_exp/nvidia/ple_mmap.py
(no output; exit 1)
```
[M] — zero hits across the whole 1010-line file.

`MmapPleTable.__init__` memory-maps **every** shard with no rank filter: `ple_mmap.py:330-334` [S]:
```python
for idx, (path, offset, rows) in shards.items():
    self.mm[idx] = np.memmap(path, dtype=np.uint8, mode="r", offset=offset, shape=(rows, row_bytes))
    self.rows_total += rows
```
and `_attach_table` *requires* all expected shards present per rank (`ple_mmap.py:870-878`, `missing = [...]` → `RuntimeError`). [S]

**Verdict**: switching to the mmap path removes the per-token all-reduce/all-gather at the PLE lookup site entirely. The trade is that every rank independently gathers the full-width rows for every token — TP-redundant I/O and TP-redundant host→device copies, in exchange for zero NCCL/RCCL traffic at that site. (The redundancy hits page cache, shared per host, so the *disk* cost is not multiplied — that last clause is my inference from `mode="r"` shared file mappings, not read from source; treat as reasoning, not evidence.)

In the test fixture each shard happens to get its own file (`tests/models/qwen4_exp/test_ple_mmap.py:112-124`, `model-ple-{layer_idx}-{shard_index:05d}.safetensors`). [S] So: "checkpoint row-block tensors, located by file+offset" is the exact statement; "not TP shards" is correct.

Contract test: `test_shard_mapping_matches_upstream_checkpoint_math_at_boundaries`, `tests/models/qwen4_exp/test_ple_mmap.py:369-411`, drives real boundary rows through `MmapPleTable.gather` and compares against the logical table. [S]

`_dequantize_embeddings` is `nvidia/ple_layer.py:634-648`; `_get_embedding_weight_scale` is `:632-634`.
